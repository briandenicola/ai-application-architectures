# The citation columns never reached the judge — and neither does the context

**Date:** 2026-09-24
**Probe:** `probes/citation_delivery_probe.py`
**Settles:** issue #14's downstream half, which shipped marked UNVERIFIED in `3705444`.

## What was claimed

`3705444` mapped `expected_citations` and `forbidden_citations` into the custom
rubric's `data_mapping` and added a `citation_discipline` dimension (weight 9) to
both rubrics. The evidence for it working was that **Foundry accepted the keys
and echoed them back**. That was explicitly recorded as insufficient, and it was.

## The experiment

Three arms. Identical `query`, and the **same canned response text in every
arm** — so a score that moves cannot be caused by anything else. The response
names `meridian-model-rate-card-2025-10` and quotes a figure from it.

| arm | channel | `forbidden_citations` | `ground_truth` |
|---|---|---|---|
| `control` | — | empty | empty |
| `custom-key` | non-standard key | names the cited doc | empty |
| `ground-truth` | documented input | empty | prose forbidding the cited doc |

Under `citation_discipline`, `custom-key` must score 1 (relies on a forbidden
id) against the control's 5. The `ground-truth` arm was added to separate "the
column does not flow" from "the input *name* is not recognised".

The evaluator version was pinned to the newest version **confirmed to contain
the dimension**, so "the eval bound to v1" could not masquerade as "the
dimension is inert".

## Result

```
control       : 1
custom-key    : 1
ground-truth  : 1
```

All three identical, all three scored 1.0 (the maximum). In every arm the judge
praised the response for "properly citing the authoritative rate card" — the
exact document one arm forbade.

## Why

The rubric's `data_schema` is **generated by the service**, not authored in our
YAML. Read back from the published rubric:

```
data_schema.properties = query · response · messages · tool_definitions
```

That is the entire accepted set for a `type: rubric` evaluator. Both rubrics
show the same four (`meridian-finops-defensible-answer` v2,
`meridian-compliance-safe-answer` v4).

Anything mapped to a name outside that set is **silently discarded**. No error,
no warning — the `data_mapping` is accepted and the value never arrives.

This corrects a belief recorded in earlier sessions: the accepted inputs are
*not* `query`/`response`/`context`/`ground_truth`. For rubric evaluators
`context` and `ground_truth` are not accepted either.

## Consequences

**1. `citation_discipline` is inert in both rubrics.** Nine points of weight
that cannot move. It is not a control and must not be demonstrated as one.

**2. A second, pre-existing problem of the same shape.** `attributed_figures`
(compliance, weight 10) and `no_fabricated_figures` (finops, weight 10) both
instruct the judge that every figure "must appear in the retrieved context".
**`context` is not an accepted input, and no tool output is exposed.** The judge
has never been able to perform that check.

These two dimensions are *partially* functional — the judge can still see, from
the response text alone, whether a figure carries a citation at all, and whether
a stated derivation is internally consistent. But the traceability half has been
graded on plausibility, not on the corpus. Every run produced to date carries
this caveat.

**3. `rate_card_in_effect` is unaffected, and shows the pattern that works.**
It names the documents and their exact rates *in the dimension prose*, so the
judge needs no per-case input to apply it. It is the dimension that
demonstrably catches MAP-010.

## The rule this establishes

> A rubric dimension may only depend on information that is in its own prose, in
> the `query`, or in the `response`. Anything else must be proven delivered
> before the dimension is described as a control.

## Follow-up: `messages` IS a live channel

**Probe:** `probes/messages_channel_probe.py`. Two arms, **identical assistant
response** claiming gpt-5.5 output cost $50.00 in November 2025. Only the
retrieved context carried in `messages` differed — one arm supplied the 2025-10
card (which does say $50.00), the other supplied only the 2026-01 card (which
says $40.00, so the stated figure is traceable to nothing).

```
grounded   (figure IS in context) : 1.0
ungrounded (figure is NOT)        : 0.904
```

**The score moved on identical response text.** Content delivered through
`messages` reaches the judge. This is the one channel that works.

Four service constraints were discovered getting there, each a free 400:

1. `messages` may not be mixed with `query`/`response` in one `data_mapping` —
   they are distinct modes, "unified-messages" and "legacy request/response".
2. Any *supported* field present in the inline data must be mapped. So the
   item cannot merely stop mapping `query`/`response`; it must not contain
   those columns at all.
3. A unified-messages item_schema requires `evaluation_level` on the run.
4. `evaluation_level: conversation` is rejected by rubric evaluators — "does
   not support conversation-level evaluation and was skipped". Only `turn`
   works.

### But delivery alone did not fix the dimension

In the ungrounded arm the judge scored `no_fabricated_figures` **5** — full
marks — for a figure that appears in no retrieved document. The whole point of
that dimension. The score only moved because `citation_discipline` slipped to
3 on a technicality about naming the source.

So the context arrived and the judge did not use it the way the prose intends.
Delivery was necessary and is not sufficient: the dimension text says figures
must "appear in the retrieved context" without telling the judge that the
context is the system turn of the conversation it was handed.

## What is still not proven

Whether a **real agent run** can deliver its retrieved documents this way. The
probe hand-built the conversation. In a live run the harness uses
`azure_ai_target_completions` with an `azure_ai_agent` target, and whether that
path exposes the agent's retrieval tool calls as mappable messages is untested.
Without it, the channel works only for replayed conversations.
